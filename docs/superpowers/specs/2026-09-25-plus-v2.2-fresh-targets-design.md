# IRNetFree Plus v2.2 — fresh random targets, and the sync to upstream v1.14.0

Date: 2026-09-25. Amends spec §1 of `2026-09-17-plus-v2.1-scan2-server2-design.md`.

## 1. Why

The owner's words: *"وقتی از روی IP شانسی تست می‌کنم هر سری واقعاً IP های شانسی جدید تولید کنه که
جواب‌های جدید پیدا کنم، نه همون لیست همیشگی؛ و بتونم IP رنج بدم، از اونا شانسی IP در بیاره، مثلاً از هر
رنج یه تعدادی."*

What v2.1 does with a box full of ranges: `scan:start` expands them **in order** and stops at
5000 — so the Cloudflare preset always tests the first 4096 addresses of `173.245.48.0/20` and
the first 904 of `103.21.244.0/22`, and never anything else. The *Random sample* button was the
only way around it, and it **replaced the ranges with a fixed list**: from then on every run tested
those same addresses. Both are "the same list every time".

## 2. Design

### 2.1 Two ways to read the box (`pick.mode`)

- **`all`** (v2.1 behaviour, the default for a box of single addresses): every address, in order,
  capped at 5000 with `truncated` reported.
- **`random`** — *تصادفی از هر رنج*: the box keeps its ranges; **every run draws a fresh sample**,
  `perRange` addresses from each range (a range smaller than that gives all of it), capped at 5000
  in total. Ranges are drawn in the order written, so the cap cuts the last ones, not a corner of
  the first.

The draw happens in **main** at `scan:start`, not in the renderer, so the box is never rewritten
and a re-run is a new sample by construction. The renderer's old client-side sampler is gone.

### 2.2 New every time: the tested history (`pick.fresh`)

A fresh sample from a big block hardly ever repeats, but a `/22` with 20 per run repeats within a
dozen runs. So main keeps a **history of every address it has actually tested** (phase-1 results,
any mode, any engine), stored under `scanTested` as an array of IPv4 integers, most recent last,
capped at 50 000. With `fresh: true` (the default) the draw skips them; when a range has fewer
untested addresses left than asked, the rest come from the tested ones and the range is counted
in `exhausted` so the tab can say so. A cancelled run leaves the addresses it never reached out of
the history (they are added per result, not per request).

`scan:presets` reports `tested` (the count); `scan:forget` empties it. Nothing else is remembered
about past runs — results were never stored and still are not.

### 2.3 Interfaces

```js
// targets.js
drawTargets(text, { perRange, max, exclude?: Set<int>, rng? })
  → { ips, errors, ranges, exhausted, truncated }
//   ips: distinct dotted quads; ranges: how many parsed; exhausted: ranges that had to repeat
// index.js
scan:start  req.pick = { mode: 'all'|'random', perRange: 1..5000 (20), fresh: bool (true) }
            reply adds { ranges, exhausted } in random mode; `truncated` as before
scan:presets → { ..., tested }        scan:forget → { ok: true, tested: 0 }
// the remembered request (`scan`) carries `pick`; a v2.1 memory without it reads as mode 'all'
// preload / web-api: scanForget()
```

### 2.4 UI (the addresses card)

Under the box: *رنج‌های کلودفلر* · *از فایل* · a two-way segment **همهٔ آدرس‌ها | تصادفی از هر رنج**.
In random mode a row appears: *از هر رنج* `[20]` · ☑ *فقط آدرس‌های تست‌نشده* · *فراموش کردن تاریخچه*
with the history count next to it. The count line reads *{r} رنج → هر اجرا {k} از هر رنج ≈ {n} آدرس*
while typing, and after a start adds *{n} رنج تمام شده* when the draw had to repeat. The *Random
sample* button and its number are removed (they were the fixed-list trap).

## 3. Gates

`npm test` (targets: per-range counts, cap, exclusion, exhaustion fallback, seeded determinism,
overlap dedupe; handlers: seven channels, `pick` sanitised and remembered, history recorded and
honoured, forget); the renderer contract; `npm run validate` on both cores; `probe:reverse` 2/2;
a headless walkthrough of the tab in fa and en.

## 4. The sync

Upstream v1.8.0 → v1.14.0 (216 commits, 161 files) merged 2026-09-25; six conflicts, each the
Plus hook next to an upstream edit. Plus-specific fallout: the new OpenWrt release job uploads
as `IRNetFree-Plus-OpenWrt`; the ready-to-show sandbox in `tests/desktopLifecycle.test.js` gets a
`const xserver = null`; `probe:reverse` / `probe:dns` are now real npm scripts. The ipk itself
keeps upstream's `irnetfree_<ver>_all.ipk` name and package id: a router runs one or the other.
