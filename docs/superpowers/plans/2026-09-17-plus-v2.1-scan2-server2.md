# Plus v2.1 — Scan v2 and Server v2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Spec: `docs/superpowers/specs/2026-09-17-plus-v2.1-scan2-server2-design.md` — authoritative for every interface named here.

**Goal:** A two-phase IP scan with per-stage concurrency and trustworthy speeds; the Server tab rebuilt on the 3x-ui model (inbound table with tags, 3x-ui client fields, outbounds with tags, a routing-rules table, a reverse wizard that writes ordinary tagged outbounds and rules) plus a `coreChannel` so the official core can follow the 26.9.x pre-releases.

**Architecture:** Same fork rules as v2.0: everything under `src/main/xserver/*`, `src/main/scan/*`, `src/renderer/plus/*`; upstream files get marked hook lines only (this release: `DEFAULT_SETTINGS.coreChannel` in both mirrors, three lines in `downloader.js`, none in the renderer). Model v2 replaces the v1 shape behind a migration; the UI is a rewrite with sub-tabs.

**Tech Stack:** Node 22 core only, `node --test`, the two xray cores in `bin/` (official 26.3.27, PattN 26.9.13 after `npm run get-xray`… — the ones present are 26.3.27 and 26.9.1; both accept everything below), `xray run -test`. Version 2.1.0, tag `v2.1.0` pushed **alone**.

## Global Constraints

- Node core only; `dependencies` stays empty. Every shipped file must parse (`tests/syntax.test.js` compiles them) — no `'` inside a single-quoted i18n string (use `’`).
- `npm test` green; `npm run validate` green on both cores; `npm run probe:reverse` 2 pass; `node scripts/probe-dns-leak.js` green; the headless render check of both tabs before the tag.
- Both mirrors build the same `ctx`; modules expose `register(ctx)`; desktop-only behaviour decided from `ctx.isElectron`.
- Renderer: `t()` everywhere, keys once per language in `plus/*.i18n.js`, logical CSS, tokens, no inline styles, `[hidden]`, every looked-up id in `index.html`, classes styled.
- Owner's machine: never bind `0.0.0.0` in a test; never `netsh`/`schtasks`; never kill `IRNetFree.exe` or its `xray.exe`; never ports 10808/10809/10085/10818/10819/10095; headless checks on `--port 39xx --data-dir <temp>`; kill the node process afterwards (`app:quit` does not exit it).
- Commits in the owner's name only, no `Co-Authored-By`. Subagents do not commit.
- `routing.rules` order is load-bearing; the first enabled outbound is the default exit.

Order: wave 1 = {Z1, Z3} in parallel (disjoint files) → wave 2 = {Z2 after Z1, Z4 after Z3} → wave 3 = Z5 after Z2 → W: integration, gates, docs, v2.1.0.
